# SoulEngine v2.0

![C++ Standard](https://shields.io)
![License](https://shields.io)
![Memory Allocation](https://shields.io)
![Binary Size](https://shields.io)

Легковесный интерпретатор математических выражений на C++17 с поддержкой динамической рантайм-рефлексии. Разрабатывался для вычисления формул на лету в игровых системах и Embedded-компонентах, где важна скорость и предсказуемость работы с памятью.

## Ключевые особенности архитектуры

*   **Не плодим объекты в цикле:** Вся память под токены, AST-дерево и стеки Дейкстры выделяется один раз при первом запуске внутри объекта `Context`. При повторных вычислениях буферы сбрасываются через `.clear()`, сохраняя выделенную емкость (`capacity`). При циклическом расчете выражений количество аллокаций через `new` / `malloc` строго равно нулю.
*   **Индексный пул памяти (Pool-of-Nodes):** Вместо классического дерева на сырых указателях (`Node*`), дерево выражений разворачивается в плоский массив `std::vector<Node>`. Адресация поддеревьев идет через обычные целочисленные индексы (`int left`, `int right`), что защищает от инвалидации памяти при росте векторов и исключает прыжки по виртуальным таблицам (VMT).
*   **Изолированная рефлексия:** Реализован синтаксис доступа к членам классов через точку (например, `player.GetHp`). Привязка методов происходит снаружи через глобальный реестр `method_registry` и шаблонные обертки `invokeWrapper`. Сами игровые классы остаются стерильными и ничего не знают про существование интерпретатора.

## Архитектурная схема конвейера (Pipeline)

```text
 Входная строка: "2 * 5 + player.GetHp + modifier"
       |
       v
 [ Лексер ] ---------> Нарезка на плоский вектор Token (без std::string)
       |
       v
 [ Сортировочная ] --> Алгоритм Дейкстры (Стеки операторов переиспользуются в Context)
 [ Станция       ]
       |
       v
 [ Таблица Node ] ---> Сборка дерева выражений в плоский вектор по индексам [left/right]
       |
       v
 [ Вычислитель ] ----> Рекурсивный обход пула + вызов метода через invokeWrapper
       |
       v
 Итоговый результат: double (115.5)
```

## Пример использования

```cpp
#include <cstdio>
#include "main.cpp" // Подключение модуля движка

class TestPlayer {
private: 
    double health = 100.0;
public:
    double GetHp() { return this->health; }
};

int main() {
    // 1. Регистрируем метод класса снаружи, не загрязняя его код
    SoulEngine::method_registry.push_back({ 
        "TestPlayer", "GetHp", &SoulEngine::invokeWrapper<TestPlayer, &TestPlayer::GetHp> 
    });

    SoulEngine::Context ctx;
    TestPlayer player;
    
    // 2. Инициализируем переменные окружения
    ctx["modifier"] = 5.5;
    ctx["player"] = SoulEngine::T(&player, "TestPlayer"); // Привязываем объект с указанием типа

    // 3. Вычисление строки одной командой
    const char* expr = "2 * 5 + player.GetHp + modifier";
    double result = SoulEngine::eval(expr, ctx); // Результат: 115.5

    std::printf("Result: %f\n", result);
    return 0;
}
```

## Сборка и метрики размера

Проект собирается через `CMake`. Для минимизации веса бинарника рантайм `iostream` полностью заменен на легковесный `cstdio`.

```bash
mkdir build
cd build
cmake -G "Unix Makefiles" ..
cmake --build .
```

*   **Физический размер файла (.exe):** ~225 КБ (статическая сборка, включающая встроенный аллокатор векторов и парсер чисел double. Весь неиспользуемый мертвый код библиотек принудительно вырезан линкером через `--gc-sections`).

## Бенчмарки и профилирование

Вся логика тестирования и контроля памяти вынесена в отдельную ветку **`benchmark-branch`**. В ней перегружен глобальный оператор `new` для точечного перехвата любого выделения памяти в куче во время выполнения.

Для проверки стабильности ядра был проведен стресс-тест на **10 000 000 (10 миллионов) итераций** с динамическими выражениями. Важно: метрики снимались для **сквозного теста (End-to-End)**, где каждая итерация заново проводила сырую строковую переменную через весь конвейер (*Лексер -> Сортировочная станция -> Рекурсивный обход*).

*   **Среднее время полного цикла вычисления (Eval):** ~650 наносекунд.
*   **Динамические аллокации в куче внутри цикла:** 0 байт (память стабильно удерживается внутри буферов `Context`).
*   **Утечки памяти и фрагментация кучи:** Полностью отсутствуют.
*   **Валидация данных (Checksum Verify):** Пройдена успешно, погрешности накопления битов отсутствуют.

## Системные ограничения (Limitations)

Ради удержания жесткого лимита в 0 байт аллокаций в рантайме, движок имеет следующие архитектурные ограничения:
1.  **Отсутствие рантайм-аллокации строк:** Интерпретатор работает только с числами `double` и указателями на объекты. Динамическая обработка и конкатенация строк `std::string` не поддерживается.
2.  **Фиксированная сигнатура рефлексии:** На текущем этапе поддерживается вызов только тех методов классов, которые не принимают аргументов и возвращают число (`double`).
